# Session 2026-09-01 — Bundle editor output-dir fixes, source profile card bugs, LLM vision gate

## Summary

Fixed four bugs across the source profile editor and bundle editor. All stemmed from the same root pattern: either hardcoded `input` directory assumptions or stale one-time state reads. Also committed two batches of pre-session work that had accumulated uncommitted.

## Changes

### `js/ui/source_profile_editor.js`

**Card subject count wrong (always 0 before profile opened)**
- The list endpoint returns `subject_count` (integer) in the summary but no `subjects` array
- Card was using `p.subjects?.length` → always 0 until the profile was opened and full data cached
- Fixed: header count uses `p.subject_count ?? subjects.length`
- Body now shows three states: chips (if subjects loaded), "N subjects · open to view" (count known but array not loaded), or "No subjects annotated yet" (genuinely empty)

**Back button DOM drift — sidebar breaks after several navigations**
- "← Back" onclick called `_render(root.parentElement?.parentElement || root)` — two levels up from the panel
- Each round-trip drifted the rendering context higher in the ComfyUI DOM, eventually breaking layout and killing all button interactions
- Fixed: `_render(root)` — panel is already the correct root

### `js/ui/bundle_editor.js` + `js/api/bundles.js`

**LLM appearance analyzer hidden even with vision model loaded**
- `_S.llmVision` was read once at `_loadAll()` time; if the model loaded after the tab was mounted the section never appeared
- Fixed: both `_renderForm` and `_renderSubjectForm` now read `window._fbtGetLlmStatus?.()?.vision ?? _S.llmVision` for the live value
- Added `document.addEventListener("fbt:llm-status", ...)` in `renderBundleEditor` to update `_S.llmVision` and re-render the form when a model loads/unloads

**Extract frame fails for videos in output directory**
- `bundlesApi.extractFrame(filename, frameIndex)` had no dir parameter
- Server endpoint hardcoded `get_input_directory()` — any file in output/ returned 404
- Fixed: `extractFrame(filename, frameIndex, dir="input")` passes dir through; server resolves `base_dir` from `dir` hint, temp frame still written to input dir (ComfyUI's `/view` endpoint requires it)

**Preprocess audio fails for videos/audio in output directory**
- Same pattern: `preprocessAudio()` had no dir, server hardcoded input dir
- Fixed: `dir` threaded through `bundle_editor.js` → `bundles.js` → `extension.py`
- All three sources handled correctly: `extract_from_video` → `b.audio.video_dir`, `extract_from_visual` → `b.visual.video_dir`, `file` → `b.audio.audio_dir`

### `extension.py`

- `_media_extract_frame`: reads `dir` from body, resolves `base_dir`, temp frames still in input dir
- `_bundles_preprocess_audio`: reads `dir` from body, resolves `base_dir`

## Key Decisions

- Temp frames from `extract_frame` always written to input dir regardless of source video dir — ComfyUI's `/view?type=input` endpoint only serves from input root, so this must stay
- `fbt:llm-status` listener added at `renderBundleEditor` level (not per-form render) — single registration, no cleanup needed since the bundle editor panel is mounted once per session
